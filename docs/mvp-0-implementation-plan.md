# MVP 0 Implementation Plan

This plan turns the product requirements, architecture, and roadmap into the
first implementation slice. The product requirements remain authoritative for
domain behavior; this document records the decisions made for MVP 0 delivery.
The [MVP 0 UI/UX plan](mvp-0-ui-ux-plan.md) defines the browser information
architecture, responsive layouts, interaction states, and accessibility
behavior for this slice.
The approved [MVP 0 visual design](mvp-0-visual-design.md) defines the styling
tokens, shared component treatment, and accessibility standard. These are MVP 0
implementation and completion requirements.

## Goal and completion criteria

MVP 0 is a runnable, mobile-first walking skeleton proving:

```text
Keycloak -> Next.js -> Symfony API -> PostgreSQL
```

A user can sign in, create and edit workspaces, switch between them, and remain
isolated from another user's workspaces. API, browser, and end-to-end checks
run in GitHub Actions using the repository's container workflow.

MVP 0 does not include invitations, sites, locations, assets, schedules, jobs,
attachments, offline synchronization, email, or production hosting hardening.

## Authentication and identity

- Add a pinned Keycloak development service to Compose with an imported
  `wrenchbase` realm and two verified development users.
- Configure a public web client for Authorization Code with PKCE (S256), with
  implicit and password/direct-access grants disabled.
- Use `oidc-client-ts` with `react-oidc-context`; configure both its user store
  and authorization-request state store to use `sessionStorage`, request
  `openid profile email`, renew tokens, and use provider logout. Remove callback
  parameters from the URL after sign-in.
- Map `email` and `email_verified` into Keycloak access tokens and cover the
  mapping with an authentication integration test; do not rely on ID-token-only
  claims for API provisioning.
- Keep the production issuer configurable. The API remains provider-neutral.
- Use Symfony's built-in `OidcTokenHandler` with discovery, cached JWKS,
  issuer/audience/expiry validation, and `sub` as the external identity key.
  Add `web-token/jwt-library`, `symfony/cache`, and `symfony/intl`; declare
  `ext-intl` and `ext-gmp` as Composer platform requirements and install both
  PHP extensions in the API image.
- Require a provider-verified email. Persist `(issuer, subject)` as the stable
  external identity and synchronize verified email, display name, and an
  optional avatar without storing access or refresh tokens.

## API contract

Use JSON:API 1.1 with `application/vnd.api+json` for successful and error
documents. Implement a small internal document/error layer rather than adding
an unverified framework bundle.

Expose these endpoints under `/api/v1`:

```text
GET   /me
GET   /workspaces
POST  /workspaces
GET   /workspaces/{workspaceId}
PATCH /workspaces/{workspaceId}
```

`GET /me` returns a `users` resource with `displayName`, verified `email`, and
optional `avatarUrl`. Workspace resources return `name`, `locale`, and
`defaultCurrency`, plus resource metadata containing the opaque revision and
the caller's role and capability strings.

Initial capabilities are `workspace.read` for owners and members, and
`workspace.update` for owners. Clients never derive capabilities from roles.

Workspace creation is available to any authenticated user at any time. It
requires a trimmed name of 1–100 grapheme clusters, a canonical BCP 47 locale,
and an uppercase ISO 4217 currency. The creator becomes the first owner.

Use UUIDv7 for all domain resource identifiers, generated by the application
and serialized as canonical lowercase UUID strings. Store them in PostgreSQL's
native `uuid` type.

Use cursor pagination for workspace collections with `page[after]` and
`page[size]`, default size 25, maximum size 100, and stable sorting by immutable
creation instant and UUID. Cursors are opaque to clients. Do not implement
`include`, sparse fieldsets, arbitrary filtering, or arbitrary sorting in MVP
0; reject unsupported query parameters with a `400` JSON:API error instead of
silently ignoring them.

Return stable JSON:API error codes for invalid tokens, missing verified email,
validation failures, authorization failures, unsupported media, unsupported
queries, stale revisions, and idempotency misuse. Include JSON Pointer sources
for field errors and a correlation ID in the response header and error metadata.

## Concurrency and idempotency

- Workspace responses include an opaque resource revision in metadata and a
  strong, representation-specific `ETag`. Because role and capabilities are
  caller-specific, derive the ETag from the workspace revision, the caller's
  membership revision, and the actor identifier; do not reuse one ETag for
  different representations.
- `PATCH` requires `If-Match`. Return `428` when it is missing, `412` when it
  no longer matches the caller's current representation, and `409` for a valid
  command that conflicts with domain state. After authorization and ETag
  validation, apply the workspace resource revision as the persistence
  compare-and-swap value.
- `POST /workspaces` requires a frontend-generated UUID in `Idempotency-Key`.
- Store the actor, optional workspace, key, operation, SHA-256 request
  fingerprint, successful status, JSON response, completion time, and fixed
  90-day expiry in PostgreSQL. Enforce uniqueness per actor and key.
- Create the workspace, owner membership, audit records, and completed
  idempotency result in one transaction. Replay the stored response for a
  matching key and fingerprint; reject a different operation or payload with
  `409`; do not retain validation or transient infrastructure failures as
  completed results.
- Add a cron-ready command to prune expired idempotency records.

## Persistence and tenancy

Create migrations for `users`, `external_identities`, `workspaces`,
`workspace_memberships`, `idempotency_records`, and `audit_events`. Use UTC
instants and application-generated UUIDv7 values.

Use shared PostgreSQL tables with explicit workspace scoping. Every future
tenant-owned table receives a non-null `workspace_id`; composite keys and
foreign keys prevent cross-workspace references. Repository methods require
workspace context, and authorization occurs before resource lookup. A valid
identifier from another workspace returns `404`.

Introduce a workspace database-context abstraction in MVP 0. Use a privileged
migration role and a restricted runtime role. Do not enable RLS on control-plane
tables such as users, identities, memberships, and workspaces. Enable
PostgreSQL Row-Level Security for tenant-owned domain tables when MVP 1 adds
sites, locations, and assets, using transaction-local workspace context as a
defense-in-depth layer rather than as the capability system.

Record identity linkage, workspace creation and updates, and membership events
in the audit table. Never store bearer tokens in the application database.

## Browser application

Add TanStack Query, Zod, Vitest, Testing Library, `oidc-client-ts`, and
`react-oidc-context`.

Implement:

- public sign-in and OIDC callback handling;
- no-membership onboarding;
- workspace creation and basic settings editing;
- the explicit `/workspaces/{workspaceId}` route and workspace switcher;
- loading, empty, unauthorized, not-found, validation, network, and stale
  revision states; and
- logout through the identity provider.

Use application boundaries and Infrastructure adapters for HTTP, OIDC, and
JSON:API parsing. Keep Next.js delivery files thin. Persist only the last
selected workspace UUID in `localStorage`; meaningful server data, drafts, and
tokens do not use `localStorage`.

Authenticated MVP 0 routes are client-composed because bearer tokens exist only
in browser `sessionStorage`. Do not perform authenticated API prefetching in
Server Components or copy bearer tokens into cookies. A later delivery-specific
session or backend-for-frontend design requires a separate architecture
decision.

The HTTP adapter attaches bearer and JSON:API headers, validates responses,
maps JSON:API errors to presentation states, exposes ETags to the update use
case, and reuses one idempotency key across retries. On a `412`, preserve the
user's entered values and offer a reload-current-state action.

Configure narrow CORS support for the web origin, required request headers,
and exposed `ETag`, `Location`, and correlation headers.

## Testing and CI

API tests cover OIDC validation and provisioning, access-token email claim
mapping, verified-email enforcement, workspace ownership and capabilities,
cross-workspace `404` behavior, owner updates, member rejection, revision
statuses, idempotency replay and misuse, caller-specific ETags, unsupported
JSON:API queries, JSON:API documents, and audit events.

Web tests cover authentication routing, onboarding, workspace switching,
capability-driven controls, JSON:API parsing, retry key reuse, stale-edit
recovery, and keyboard-accessible forms.

Add a Playwright golden path using the real Compose stack and serial Chromium:

1. Sign in through Keycloak as the first user.
2. Create two workspaces and switch between their explicit routes.
3. Edit a workspace and exercise stale revision handling in two tabs.
4. Sign in as a second user and create a private workspace.
5. Verify the first user receives `404` for that workspace's route and API
   request.
6. Log out through Keycloak.

Run the primary path at a narrow mobile viewport and retain traces, screenshots,
and the HTML report on failure. Add `make web-test`, `make e2e`, and include
API QA, web checks, and end-to-end checks in `make check`. Add a GitHub Actions
workflow for pull requests and pushes to `master`.

## Delivery sequence

1. `docs(project): define the MVP 0 walking skeleton`
2. `chore(test): establish web tests and GitHub Actions`
3. `feat(auth): add provider-neutral OIDC authentication`
4. `feat(workspaces): deliver workspace onboarding and tenancy`
5. `test(e2e): cover the authenticated workspace golden path`

Each commit includes directly related tests, passes the relevant checks, and
updates the affected client and contract together.
