# Canonical PRD Reconciliation

This is approved reconciliation evidence for the canonical UX migration.

## Reconciliation rule

The canonical PRD remains the authority for product behavior, scope,
terminology, and milestone boundaries. `DESIGN.md` and `EXPERIENCE.md` reference
it through `sources:` and do not restate it. This artifact records where each
PRD heading constrains the UX spines.

The destination labels are:

- **DESIGN** — visual identity, tokens, presentation, or visual accessibility.
- **EXPERIENCE** — information architecture, behavior, interaction, state,
  accessibility behavior, or a key flow.
- **RETAIN** — remains owned by the canonical PRD or a focused technical
  document; the UX spines reference it rather than taking ownership.
- **DEFER** — a later-milestone UX concern that is preserved but not expanded
  into unsupported screens during this migration.
- **UNRESOLVED** — a conflict or missing decision that requires an authority
  decision before the affected UX can be finalized or implemented.

## Conflicts and gaps

### Unresolved

1. **UX-OQ-1 — active Workspace on authenticated no-Membership surfaces.** The
   PRD requires explicit Workspace context for Workspace-scoped routes while
   also requiring authenticated onboarding for a person with no Membership.
   UX sources say the active Workspace and Workspace switcher appear on every
   authenticated screen. The exception for onboarding and authentication
   transition surfaces requires explicit approval.
2. **UX-OQ-2 — MVP 0 settings and stale-edit scope.** FR-2, UJ-1, the approved
   MVP 0 contract context, and the MVP 0 UI/UX plan include Workspace locale and
   currency editing plus stale-edit recovery. The PRD's milestone summary lists
   settings under MVP 1. Do not silently select a boundary.
3. **UX-OQ-3 — untouched fields during stale-edit rebase.** FR-34 requires input
   retention and deliberate reload/resubmission, but it does not decide whether
   **Review my edits** adopts server changes to fields the user did not edit.
4. **Interface language and fallback.** The PRD defines Workspace locale and
   canonical locale/currency values but does not define supported interface
   languages, selection, or fallback. Workspace locale must not be treated as
   interface language without a decision.
5. **PRD OQ-1 through OQ-7.** These remain unresolved exactly as recorded in
   the PRD and at their stated phase gates.

### Resolved by PRD authority

- A source statement that an explicit Requirement link affects Due Work is
  narrowed by FR-20 and FR-22: a planned link adds `planned`; only a completed
  Work Item explicitly fulfilling a Requirement resets Due Work.
- Source wording that any Member can act does not permit role inference in the
  client. FR-4 requires returned Capabilities to control exposed actions.
- Use canonical `notification center`, Due Work, Work Item, Requirement,
  Capability, and `needs_review`; source variants do not replace PRD terms.
- “Intermittent connectivity” does not broaden offline scope. FR-32 and FR-33
  define the supported cache, authoring, synchronization, and conflict limits.

### Coverage gaps that remain deferred rather than invented

- The PRD defines product behavior for MVP 1 through MVP 5 but generally does
  not define complete route maps, screen inventories, responsive layouts, or
  component interactions for those milestones. Those UX details remain
  deferred to milestone-specific planning.
- The PRD supplies no visual token values, component styling, typography,
  shape, elevation, or motion system. DESIGN obtains those decisions from the
  approved visual-design source, not from inference here.
- Quantitative production targets, product-usefulness targets, trash retention,
  Job cancellation semantics, Maintenance Need literals, and invited-Member
  email defaults remain the named PRD open questions.

## Dropped qualitative detail

None. The PRD's approachable individual-to-small-team positioning, manual-led
and history-preserving principles, uncertainty honesty, practical offline
intent, audience breadth, named journeys, risks, and counter-metrics all have a
destination above. Normative product detail stays in the cited PRD rather than
being duplicated into the UX spines.
