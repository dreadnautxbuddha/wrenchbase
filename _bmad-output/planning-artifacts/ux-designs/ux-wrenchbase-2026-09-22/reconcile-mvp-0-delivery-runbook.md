# Reconciliation: MVP 0 Delivery Runbook

## Migration verdict

The runbook remains the focused MVP 0 implementation-sequencing authority. It
does not replace the PRD, architecture, API contract, UX plan, visual design, or
canonical UX spines. User-visible outcomes and acceptance constraints migrate
to `EXPERIENCE.md` or `DESIGN.md`; package scope, order, commands, commits, and
engineering checks remain here. The runbook is retained after UX approval.

## Conflicts and dropped-detail audit

- **UX-OQ-2** remains unresolved because Packages 9–10 place basic Workspace
  update/settings and stale recovery in MVP 0 while the PRD milestone summary
  names settings under MVP 1.
- **UX-OQ-5** remains unresolved because Package 11 requires a supported UI
  language list, selection behavior, and fallback order that no source chooses.
- **UX-OQ-6** remains unresolved because Package 9 preserves `428` as distinct
  but does not define its user-facing recovery.

No qualitative UX, visual, accessibility, state, or flow detail is dropped.
Implementation packages, commands, commit subjects, dependencies, and test
mechanics remain in this retained focused runbook.
